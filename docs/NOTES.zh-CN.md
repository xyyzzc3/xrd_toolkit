## 命令行参数

四个脚本都支持两种方式选文件：`--file` 指定单个文件；不带 `--file` 则弹出交互菜单，列出 `data/` 里所有数据文件按编号选择（`1,2` 多选、`all` 全选）。输出都在 `outputs/{数据名}/` 下。三个消费脚本用 `--config 条目名` 选几何配置（默认 `lmfp1_lab6`）；交互模式下选完文件会再弹一个配置菜单（回车 = 默认条目）。

<details>
<summary><b>衍射图查看</b> — <code>scripts/view_diffraction.py</code></summary>

```bash
python scripts/view_diffraction.py --file data/xxx.tif --angle 0 --outdir outputs
```

- `--file`：衍射图像路径（.tif / .edf / .cbf）
- `--center`：环圆心坐标 cx,cy，不填则用选中配置的束心
- `--config`：几何配置条目名（config.py 的 `CONFIGS` key，默认 lmfp1_lab6）
- `--angle`：剖面线与水平方向的夹角（度），默认 0
- `--outdir`：PNG 输出目录，默认 outputs/

![过圆心的强度剖面](../showcase/lab6/radial_profile.png)

</details>

<details>
<summary><b>几何校准 + 1D 图谱（LaB₆ 标样）</b> — <code>scripts/calibrate_integrate.py</code></summary>

```bash
python scripts/calibrate_integrate.py --file data/xxx.tif --wavelength 0.1223 --pixel 200 --dist0 1600
```

- `--wavelength`：X 光波长（Å）
- `--pixel`：探测器像素尺寸（µm）
- `--dist0`：探测器距离初值（mm），pyFAI 自动精修出精确值
- `--center`：环心初值 cx,cy（像素，不传则自动定位，精度 <1 px）。偏置束心（部分环）数据必须显式传入：自动定位需要完整环，且该摆法下精修不可靠——距离/倾斜角请用居中标样图像标定
- `--max-rings`：参与校准的环数（默认 16）
- `--range`：2θ 区间——`full` / `auto`（默认，材料专属标准）/ `lo,hi` 度（如 1.3,7.3）；完整版 txt 永远保存
- `--outdir`：输出目录（默认 `outputs/`）

流程：LaB₆ 峰位校准（pyFAI `GeometryRefinement`）→ 方位角积分（2D→1D）→ 输出 `calibrated_2th.txt` + `calibrated.png`（红虚线 = 理论峰位）。代码在 `xrd_toolkit/services/integrator.py`。精修完成后会打印一段可直接粘贴进 `config.py` `CONFIGS` 的条目模板，改好 key 即完成新批次登记（脚本自己从不改那个文件）。

</details>

<details>
<summary><b>全角度积分（2D → 1D 标准谱）</b> — <code>scripts/integrate_pattern.py</code></summary>

```bash
python scripts/integrate_pattern.py --file data/xxx.tif
```

用选中的几何做 0°–360° 完整方位角积分，输出标准两列 txt（2θ(deg), intensity）+ PNG。可用 `--dist`、`--poni`、`--wavelength` 覆盖几何；`--range full/auto/lo,hi` 控制画图与 `_auto` 裁剪版 txt 的区间（完整版永远保存）。

</details>

<details>
<summary><b>扇形积分 + 瀑布图</b> — <code>scripts/sector_waterfall.py</code></summary>

```bash
python scripts/sector_waterfall.py --file data/xxx.tif --n-sectors 36
```

把 0°–360° 方位角分成 N 个扇区分别积分（默认 36 个，每 10° 一个），输出每扇区的两列 txt（`outputs/{数据名}/sectors/`）+ 一张原强度堆叠瀑布图（36 条曲线沿 Y 轴错开、**行距统一 = 全场峰值 × 0.7**，每条画到自己强度变 0 处——右端阶梯即各扇区衍射环被探测器边缘切掉的位置），用于检查方位均匀性（大晶粒、择优取向会表现为强度集中在少数扇区）。行距刻意**不**按各扇区自己的峰值来：那等于把每行都缩到各自高度，扇区之间的强弱就没法横向比了（用户 2026-09-26 定的规矩："不要按照各自的最高峰归一化，所有的图"）。界面里的瀑布图同口径，另外会把处理链（背景 / 平滑 / 裁剪）逐扇区跑一遍——把压扁其他峰的巨峰裁掉之后，弱扇区才看得清。支持 `--range full/auto/lo,hi`。

</details>

## 校准

[校准] 入口打开校准页：第一栏是**配置条目操作区**——[编辑当前配置…] 加 [加载参数] / [保存参数] / [删除] / [保存为配置]——紧跟在坞顶"几何配置"那一行下面，因为这些按钮作用的就是那一行选中的条目。往下才是**三列表**（**当前配置** + 两个对比位 **A** / **B**，三列都可以从"跑过的东西"里选），再往下是两个动作块——**自动**（定位环心并精修 / 在当前配置上再精修）与**手动**（图上点环：≥3 点、覆盖 ≥2 环、±0.5° 自动吸附）。

当前配置一开始是**从选中条目借来的原始几何**；[编辑…] 可以换成别的条目预填或直接手输，**只要手改过就标成"自定义"**、之后不被自动替换。**每个结果都按自己的名字累积**（原始 / 自动1 / 手动1 / 精修1 …），并按 A→B→A 轮换填进对比位——除非你手动选过那个槽（选过就**钉住**，新结果不再覆盖它）。

**"用的到底是哪一份"：你按钮跑出来的结果一律成为当前配置**（2026-09-30 改的口径，原话"只要是用户操作的，无论自动手动精修都填入当前，让用户看到变化"）——青环立刻跟着动，日志把"好了/差了多少"写出来（`当前配置 → 手动1（环位偏差 0.50 px，比 借用 lmfp1_lab6 的 0.20 px 差 0.30 px）`）；覆盖你手输/手改的几何时会点明"那份仍在结果列表里，随时能选回来"。原先的门槛（要赢过当前配置 **0.05 px** 才替换，理由是同一张图重复跑环位只抖 0.014~0.029 px）现在**只用来分档措辞**（优于 / 差不多 / 差多少），不再决定换不换——阈值判得再对，青环不动，用户也会以为精修没生效。校准图标题也写明了这一点：`青环 = 当前配置：<哪条结果> · 环位偏差 X px`。这一页上 Δ 行与结论是**同一个参照**，而且**永远是「当前配置」**：Δ = 该列 − 当前配置（当前配置那一列自己写「基准」，不再是一个看着像"没数据"的破折号；结论 = A、B 两个候选分别 vs 当前配置，两边的名字和数字都写全——"A 比 当前配置 好 0.32 px（环位偏差 当前配置 0.73 px ｜ A 0.41 px）"）。这个参照系来回走过三步：最早两处各说各的（用户 2026-09-27："对比基准和结论表述不清，不知道是谁在和谁比"——那会儿基准只挪 Δ 行，结论写死在"当前配置"上，切基准时结论一个字都不变，即用户 2026-09-28 第 2 条"数据结论不受对比基准的影响"）；随后加过一版「对比基准」下拉框同时管两处；2026-09-30 把下拉框整个删了（用户："直接把对比基准删了，直接出结论当前配置和 a、b 对比分别怎么样，随着用户选择 ab 当前进行变化"）——换掉 A/B 槽里钉的结果，Δ 行与结论立刻跟着变，也就没有"基准选着 A、结论在讲 B"这种要绕一下的表述了。**判环可疑时按尺度重判**（2026-09-30）：点图判环 = 拿当前几何把点换算成 2θ、找最近的理论环（容差 0.5°），而低角侧没有更低的环可判——**距离错一个比例，最里面几个真实环会被压到第 0 环**（用户原话："第 0 青环里面套了两个真实的环，点击真实的环，里面的两个环都会标记为第 0 环"）。现在手动精修前先看一眼：**同一个环号横跨了两个半径**（差 >15%）就扫 7 个距离尺度（0.85~1.20）、各自重判环再拟合，挑**环位偏差最小**的那套，日志写明换成了哪个尺度（只有好过 0.05 px 才换——与采纳门槛同一个噪声口径）；没有图像或指标算不出来时不猜、原样不动。**后手：右键某个选点可以直接改它的环号**（弹一个小输入框，位置不动、只改环号；改完按 [用选点精修] 重跑）——自动那套都没救回来时，你自己知道它该是第几环，比再点一遍碰运气可靠。

**页面顺序与下拉重复**（同日）：页面自上而下 = 操作 → 自动 → 手动 → **数据**（先跑、再看结果；用户："校准数据放最下，跟自动手动换位置"）。"当前配置"那个下拉只在**没指向结果**时（手输的自定义 / 借来的条目）才插一个显示项——指向结果时列表里只有它自己（原先会出现两条同名项：用户报"自定义 自定义1，当前选中 2 在选项中还有 2"）。

PONI 与倾斜角标 ⚠——它们与距离/波长退化，差异大不等于更准；自洽残差**不入表**（它量的是迭代收敛，不是准不准）。

图上那圈青线是**当前几何预测的真实环**：每个点都由 pyFAI 的 2θ 场反解而来，倾斜探测器上就以它本来的椭圆样子画出来——用"圆心 + 半径"的正圆近似会整体偏 8~23 px（环的公共圆心是直射束落点，不是 PONI）。点图判环用同一套几何，因此点你看到的那条线不会判成隔壁环号；若当前几何把 16 条环全推出探测器（距离/像素尺寸/波长填错或精修跑出离谱解），面板会在图上打红字、并在日志里明说（连半径范围一起报出来，一眼看得出差几倍），而不是默默画一圈看不见的线。**视野本身永远不动**：始终是图像那一框——衍射图是唯一不动的参照系，青环围着它动。想看环跑到哪去了得自己动手：面板上的 [看环全貌] 开关（默认关，每次开面板都复位）会把视野放大到包住整组环，图像这时会缩成中间一小块——那正是这个开关的用途。

**引擎指标。** 每次校准都会在日志里附上：环位偏差中位（px，括号里是精修前初值的同一数字）、16 条环里完整跑出来的条数、以及逐环反推的 LaB₆ 晶格常数离散度。它们量的是拟合残差量不到的东西——实测过残差 0.0000°（看着完美）而环位偏 9.6 px 的情况（故意喂一组偏离真环的点），因为残差是迭代自洽量、不是精度指标。环位偏差抓"整体几何错"，晶格常数离散度抓"某些环与单一几何不符"（环号认错、探测器畸变、某条峰被顶偏）；距离与波长在标样上一阶简并，所以距离误差几乎不推动离散度，别用它判断距离。

**像素尺寸是道闸，而指标抓不到它填错。** 像素尺寸必须确认过才允许跑校准，而且只有**像素值真的变了**才会再次要求确认。距离、波长、像素尺寸只以**乘积**进入计算：像素填错时环照样严丝合缝，但报出来的距离（以及由它推出的东西）整体错同一个比例。保存也走同一道闸：[保存为配置] 在没确认时只记一行日志、不落盘——条目会被别的批次和命令行脚本原样拿去用。

**参数进出。** 新批次从「当前配置」出发：[编辑…] 里可借另一条条目预填或直接手输（**束心行/列也在这一页改**——用户 2026-09-28 第 2 条之前，对话框里根本没有这两个框，"从条目预填"也只搬 7 个数字、留下旧束心，而束心正是校准最常动的东西），也可用 [加载参数] 导入 .poni。手输/手改的几何会**进累积结果列表**（「自定义1」「自定义2」…，用户 2026-09-28 第 1 条：改之前它只活在"当前配置"那个变量里，没有户口——A/B 下拉里选不到、切走就找不回来、也不能当对比基准；现在它与自动/手动结果一视同仁，重新选中它还会恢复"自定义"保护标记，免得下一次自动结果把它悄悄替换掉）。[保存为配置] 与 [保存参数] 保存的都是**当前配置**——借来的、手输的、采纳来的都行——[保存为配置] 写命名条目并写入血缘（`derived_from`、`method`、`created`），存成本地 config_user.json（不进 git）：立即出现在"几何配置"下拉框并自动选中，重启仍在，命令行脚本同样可用 `--config` 选取。几何配置下拉框自己住在**参数面板顶部钉住的一行**里，五个入口页都看得见、也都换得了；悬停它就能看到当前条目的像素尺寸 / 波长 / 距离。分析页与几何有关的部分是**只读**的：只负责选条目。校准页上这个下拉框照样能换（提示里补一句：校准跟的是那一页自己的「当前配置」，不是这里选的条目），因为作用在这条条目上的按钮——[加载参数]/[保存参数]/[删除]——就住在校准页。校准模式下同一行还多一个 [返回分析模式] 出口。[保存参数] 把**当前配置**（校准页表里第一列那个，含手输）写成 pyFAI 通用交换格式 `.poni`（探测器距离、中心点 poni1/poni2 米制坐标、像素尺寸、波长、倾斜角 rot1/rot2；掩膜文件为可选项——引擎尚未支持掩膜且 .poni 格式本身无掩膜字段，故不写），日志里写明存的是哪一份；用户 2026-09-28 第 2 条之前，它存的是坞顶选中条目的几何——手输改完按保存，导出的还是旧条目的数字（"改完保存，文件里是旧的"），现在与 [保存为配置] 同一个口径。[加载参数] 读 .poni 存成命名条目（与 [保存为配置] 同源）。导入或保存的用户条目可用 [删除] 移除（内置条目置灰不可删）：删除前弹确认框，删后自动回退默认条目。

## 自动 2θ 区间选择

`--range auto`（默认）用材料专属标准定区间：下界按标准选取（粉末样品：第一个已知峰 − 0.3°；LaB₆ 标样：检测到的光环结束点 − 0.6°，≈1.0°），上界自动检测"数据失效点"。

失效判据是**相对弧覆盖率**——环上落在探测器内的方位角比例跌破自身峰值的 50%——所以一套判据适应任何束心摆法：居中摆法约 7.9°（旧的 80% 绝对判据停在约 7.44°），偏置摆法自动后移。单曲线脚本用几何精确值；瀑布图的扇区实测值晚约 0.5°（10° 扇区量化）——两者互相印证，只有真不一致才告警。完整区间版 txt 母版永远保存。

## 偏置束心（部分环）

束心故意打在探测器边缘或角落的数据（每条环只拍到一部分，但因此能看到更高 2θ 的环）全程支持：pyFAI 的径向分箱不可靠时自动切到自研的 numpy 极坐标积分（pyFAI 按探测器中心分箱，合成环上验证过），扇区 χ 标签报实际覆盖的方位范围而不是假的 360°，瀑布统计只对真有信号的扇区取平均。这类数据集的**校准**应当用居中摆法的标样图做（距离/倾斜角是仪器属性）；`--center` 的说明里写了这一点。

## 处理（背景扣除 / 平滑 / 裁剪）

「处理」页三项，**都是可选项**（不勾就是没做），都**改参数即重画**（毫秒级，不需要重新积分），
都能**一键应用到整批**（[批量处理]），处理完的结果进文件栏的「处理后 …」分组。

**顺序固定：背景扣除 → 平滑 → 裁剪。** 两条边界原因：锚点在裁剪前取样（否则落在裁剪区里的
锚点取到空值，整条基线报废）；平滑看不到空洞（先把完整曲线平滑好、最后挖掉那一段，切口边缘
干净——反过来会遇到"窗口一半是空值"的边缘处理，每张图的边缘都会悄悄不一样）。

| 项 | 做什么 | 参数 |
|:---|:---|:---|
| 背景扣除 | 减掉不含结构信息的加性背景（空扫相减 / 自动基线 / 手动锚点） | 见下一节 |
| 平滑 | 两种方法：**滑动平均**（默认）/ **Savitzky–Golay** | 窗口宽度（**度**，不是点数——换输出点数后"平滑了多宽"不变）；SG 另有多项式阶数（2~3 常用） |
| 裁剪 | 把指定 2θ 区间从曲线里挖掉（图上那段空着） | 起止 2θ + [添加]：**清单里可以放好几段**（例如同时删 2–3° 和 7–8°） |

**两种平滑怎么选（LaB₆ 标样、同一个 0.30° 窗口实测）**：滑动平均把最强峰削掉 **90.6%**、
半高宽从 0.18° 涨到 0.31°；Savitzky–Golay 只削 **82.3%**、半高宽仍是 0.18°。所以**看峰形、
量峰高/半高宽用 SG**；只想让曲线看着干净、不在意峰的绝对值，滑动平均更快更简单。SG 的代价是
接触陡边（低角鼓包）时可能压出轻微负值下冲——看背景水平时留意。

裁剪清单以**列表**为准（窗口级），勾上「裁剪区间」时若清单是空的，就把旁边填的那一段加进去
（填了起止、勾上开关 = 最自然的手势）；想再多删一段就 [添加]，[清空] 一次收回。同一段重复
添加只留一份，起点 ≥ 终点会被拒绝并说清原因。

**裁剪是"挖空"不是"删点"**：落在区间里的强度标成空值（NaN），2θ 网格与各文件长度都不变
（对比 / 热图 / CSV 的对齐逻辑因此不用改）。三个后果都是要的：

- 图上那段**空着**（matplotlib 遇到空值自动断线），纵轴自动范围**跳过它**——这正是"某个巨峰把
  其余部分压扁"时的解法；
- 处理产物里那段同样是空的，**导出的 txt/chi 里那些点不写行**，文件头写明 `processed: …` 与
  `cut: N points removed`；
- CSV 总表里那几格**留空**（不能写 0：0 会被当成真实强度参与后面的计算），表头注明哪几列有裁剪。

**产物键 = 1D 产物键 + 处理链哈希**（背景 + 平滑 + 裁剪一起算）。没开平滑与裁剪时，哈希与
"只有背景扣除"的老产物**逐位一致**——升级不会让以前存的产物失效。组名写清这一组做过什么：
「处理后 09-25 16:40（锚点 5 个（覆盖 1.29–2.7°）、窗口 2°、平滑 0.15°、删 2–3°）」——锚点那条写着它**实际覆盖的角度范围**，因为范围之外是推出来的、不是点出来的；产物元数据里另有一行机器可读的
链描述（`bg=anchor(n=5)/win=2 → smooth=boxcar/0.15° → cut=2–3°`），拿到任意一份产物都能查清它经历了什么。

**一句话记法**：1D 产物 = 积分的结果，处理产物 = 处理的结果，对比/热图/导出读处理产物（有就用，
并在日志里写明"处理产物 N 条"）。屏幕上看到的曲线与写进文件的那一条，是同一个函数的输出。

**处理页底部三个按钮**（2026-09-28 补上出口，2026-09-30 删掉 [重画]）：**[重算这张图]**（原名
"按 2θ 重算这张图"，与 1D 页同名同动作；按坞顶的 2θ 范围/点数**重新积分**编辑对象那一张——2θ 是**积分期**参数，
处理链只吃"手上那条曲线"，改之前处理页只有"重画"、改了 2θ 没有任何地方能让数据跟上，看着就是
"2θ 无效"）、**[采用这份结果]**（把编辑对象这张图上眼下这条处理后曲线**落成产物**、进文件栏的
「处理后 …」分组，单张也有交代——不用"勾上自己再点 [批量处理]"那种绕法）、[批量处理（勾选文件）]。

**"重画"不再有按钮**（2026-09-30）：[重画]（本页）跑的就是"改任一处理控件即重画"那条自动通路，
[只重画，不重算]（绘图页）与每张图标题栏的 [Home] 同源——两个都是重复入口，一并删掉。新流程
就一句话：**参数实时重画 → 放大镜/滚轮调视野 → [Save]（存的就是屏幕当前画面）**；放大过头了按

## 背景扣除

参数面板的"背景扣除"小节减掉**不含结构信息**的那部分信号：空气散射、样品非晶漫散射、荧光、探测器暗电流、直射束光晕。这一步在本数据上是必须的：两个样品的背景都朝低角抬升 3.8~5.2 倍（LMFP 1~2° 处 1429 counts，9~10° 处只有 275），所以"减一个常数"根本不行。

三种模式，**全部实时预览**（参数只改画法，缓存里的原始曲线永不被改动，因此不触发重新积分）：

- **空扫相减**——先拍一张没有样品的图逐点减掉，曝光/束流不一致时填归一化系数；
- **自动基线**——滑动窗估计背景水平，窗口宽度应取最宽峰宽的 3~10 倍（改成"窗口内直线拟合"之后可用范围从"1° 附近"放宽到 0.5~3°）。**默认 0.5°**（2026-09-26 从 1.0° 改）：LMFP 数据上 1° 窗口会把 1.6~2.6° 的宽非晶鼓包当结构留下（残留中位 34、最大 527），0.5° 能扣掉（残留中位 −1、最大 322）而巨峰高度几乎不变（2510→2516）；0.1° 也能扣掉，但骑峰更明显（峰下抬高 211 vs 142）；
- **手动锚点**——在 1D 图上点选"只有背景"的位置，锚点之间默认走**保单调平滑**（pchip：过点、光滑、不过冲），另有折线（实验室惯例）与自然样条（可能过冲）可选。**最外侧锚点之外：锚点定电平、自动基线定形状**——基线沿着自动基线那条曲线平移到你最近的那个锚点，不再拉直线出去。旧做法（按末两锚点的斜率线性外推）的斜率来自最后两个锚点，而用户在同一个位置附近点两下是很常见的：两点只差 0.02° 时，十几个 counts 的噪声被除成几百 counts/度，再乘上到数据末端那好几度，基线被凭空抬起几千 counts、整批曲线一起歪（2026-09-27：81 个文件里 68 个中招）。没有自动基线可借时，两端就保持锚点值：低角少扣是看得见、再点一个锚点就能修的；过扣是静默的，而它毁掉的是所有强度。

**自动基线的两阶段与"局部线性"。** 阶段 1 取窗口内的低分位（一个不会被峰抬高、但偏低的下限），阶段 2 掩掉峰点后给出**窗口中心处的水平**——这一步 2026-09-26 从"掩峰后取均值"改成"**窗口内直线拟合**"：陡降段上掩峰会掩掉窗口高的一侧，均值因此落到真值以下，低角系统性扣过头（合成真值实测 −139/−163/−533，窗口 1°/2°/3°），局部线性没有这个偏差（同口径 +3.7/+1.0/−9.3，平均绝对偏差 42→35、63→46、94→67）。实现是向量化的（掩膜是逐点判据 → 前缀和 + 二元正规方程，10 万点 21 ms）。

**纵轴不跟着背景跑。** 扣背景时 1D 面板的自动纵轴范围按**未扣的原始曲线**定（扣后曲线只补上界），所以每加一个锚点、每改一次窗口，框都不动、只有曲线在框里往下走——按扣后曲线算的话整张图会跟着重定比例，看着像"图在动"。


对比面板的纵轴现在同理（2026-09-26，跟在 1D 那次之后）：框由**不跑背景/平滑**的那份曲线定，但**保留归一化**（它本来就要改比例）与**裁剪区间**（剪掉巨峰仍要让纵轴放开）；于是调背景时框不动，唯一的例外是刚开启扣背景那一下下界会落到 0 附近——那是给扣完的曲线腾地方，免得它们贴在框外。
**锚点拟合方式实测**（合成真值：陡降背景 + 6 个峰 + σ=12 噪声，5 个锚点）：保单调平滑平均绝对偏差 6.1，自然样条 16.4，折线 28.8（只有 3 个锚点时 50 / 99 / 118）——所以界面默认给了保单调平滑。

扣背景时 1D 面板会把原始曲线（虚线）和基线（点线）一起画出来，边调边看扣前扣后。锚点按文件各记各的；对比 / 瀑布 / 热图跟随同一套设置（瀑布减的是**扇区均值的共同基线**，这样扇区之间的真实强度差才保留得住），[导出数据] 也可导出扣完背景的曲线。扣完的负值默认保留——噪声地板是真的，强行截断到 0 会把均值抬高约 1σ——想截断有单独的复选项。

SNIP 也实现了并实测过，但它在这些图谱上会过度扣除 43%~98%（把 2.2° 附近的宽非晶鼓包当成峰削掉了），所以界面里不提供。

**颜色跟着它所属的那张图走。** 2D 面板的色图原先写死 magma；Customize 里现在给 2D 面板多一个「色图」下拉（按面板记进快照、点 [应用] 重画），和它本来就有的「对比逐曲线颜色」并排。分工一句话：**这张图现在的颜色**在 Customize，**新图默认用什么颜色**（曲线配色色板）在参数页。

参数坞顶层固定三行：编辑对象、几何配置、**数据参数（2θ 积分范围 + 输出点数）**。范围原先只在 1D 页，想给对比/热图换范围得先走回 1D 页（用户 2026-09-27：一 d 画图时能选范围，后面处理时没法选范围，比如对比时，参数里加上）——它们本来就是「参与计算的数据参数」，和几何配置同一类，所以并排住在坞顶、四个分析页都看得见——**校准页把它收起来**（用户随后指出「校准页参数放 2theta 范围干嘛」：校准在原始图上定几何，全程不读 2θ 区间）；几何配置那一行则相反，校准页要留着，它是借用起点，也是 [加载参数]/[保存参数]/[删除] 的对象。1D 页上的**视图 2θ 范围搬去了绘图页的「1D 显示」小节**——它本来就是显示参数，而在 1D 页它紧挨着坞顶那行积分范围、长得一模一样（用户当时的话：「1d 参数页两个范围。。。」）；现在 1D 页只剩下一行范围，两个含义各住各的地方：坞顶那行管积分（改了要重积分），视图范围现在**只能靠缩放/平移**（用户的决定：「显示范围用户自己放大就行了」），那对输入框已撤——参数键还在（缩放写回、[恢复默认] 复位），只是不再有控件显示（`_param_box_set` 见不到控件就跳过；`_display_snapshot` 会把没有控件的键从旧快照带过来，免得 [应用] 悄悄丢掉显式视图范围）。热图的显示控件（色图 / 对数强度 / 归一化）现在**改了立刻重画**——原先这几个控件谁都没接，画出来的热图根本改不了颜色。

**改了还没生效的，现在有灰字说**（用户 2026-09-30："参数页显示本图的参数……如果用户改了，添加一个灰字未应用来区分，切图再切回来保持"）：参数坞显示的永远是「编辑对象」那张图的参数；你改了 2θ / 点数（要按 [重算这张图]）或显示参数（要按 [应用显示设置]）之后，对应那一行会亮一个灰字 **「未应用」**——"图上还是旧的"一眼可见，而不是靠猜。这份改动**按图记着**（记在面板上）：切走再切回来原样还在，灰字照旧亮着；改之前的行为是切图时回放直接把它冲掉、一个字都不提示。灰字量的是"控件值 vs 那张图已生效快照"的差，所以按了生效按钮它自己就灭。另外**"填了数去出图"不算未应用**：你填 2θ=2.5 按 [出图] 出一张新图，2.5 是给那张新图的**指令**、已经被用掉了——不区分的话，切回原来那张图会凭空冒出一个"未应用"（有两条老测试正是这么挂的）。自动开关（纵轴自动 / 自动对比度 / 热图自动范围）勾着时，它那对上下限是程序算完填进控件的展示值、不算用户改动——不排掉的话灰字会永远亮着（探针实测踩到过）。

**扣背景配方按文件记。** [批量处理] 原先只把模式/窗口写进「当时开着」的面板（锚点本来按文件存）：给 A 扣完、批量，再点开 B，它显示「不扣」——B 明明有产物。现在配方落进 `proc_recipes[path]`（每个目标都写，`anchor_source` 记着借的是哪个文件的锚点），处理页把它写成一行字（「本图配方：自动基线、窗口 0.3°、锚点 21 个（覆盖 1.29–2.70°）…（锚点来处：a）」）。**它是记录不是动作**：打开原始条目永远画原始曲线——早先那版会按配方回填快照，于是处理过的文件「点开就是扣过的样子」，用户 2026-09-27 当晚报的就是它（「原始数据现在会被改变…按理来说原始数据应该打不开的，因为是原始 tif」）。想套用要显式按 [套用]，或者去文件栏点「处理后」那一条看结果。这份形状同时也是**命名配方**的形状：[保存为配方…] 把模式 / 窗口 / 锚点**位置** / 平滑 / 裁剪写进 `outputs/recipes.json`（见 services/recipes），以后任何一批都能套——锚点的**强度**永远按每张图自己的曲线重取，这正是 [批量处理] 一直以来的口径。这个按钮 2026-09-28 之前**从来没成功过一次**：`app._save_recipe_dialog` 里调了 `_proc_settings`，而这个名字在 app 模块里从没导入过——每次点击都是 NameError，日志区一个字都没有（用户报"保存无效"，探针当场复现；`outputs/recipes.json` 在那之前根本不存在）。两个显示问题同批修掉：配方下拉/「本图配方」那行原先在**记录配方之前**就填好了（`_sync_bg_rows` 跑在 `_refresh_proc` 前面），于是刚调完参数那一刻下拉里只有占位项、按 [套用] 只得到"先在下拉里选一份配方"——现在记录完就地刷一次；下拉默认选中项是"本图配方（这个文件）"，它**就是**屏幕上这套，按 [套用] 看不出变化是正常的，要看效果请在下拉里挑"已保存：…"。落在某张图 2θ 范围外的锚点会被丢掉并报一行（钳到端点值是错的，而且看不出来）。同一思路往下走一层就是「自动 + 锚点校正」（用户 2026-09-27）：自动基线按你点的锚点做校正——锚点处的残差用保单调插值摊到全曲线，基线严格过你的点、形状仍是自动那份；所以锚点那行现在在 **auto** 模式也露出来，窗口默认也跟着改（1.0° → 0.5° → 0.3°）。**2026-09-28 用户把默认从 0.3° 再收到 0.2°**（原话「默认值 0.3 改成 0.2」）：实测这批 LMFP 上 0.3° 仍偏宽（背景点残差中位 −1.5、1% 分位 −30、峰翼处最狠 −889，窗口越宽峰翼被平掉得越多）。改的是**默认值**、不是算法——`BG_ALGO_VERSION` 没动，按 0.3° 算过的产物键里带着 0.3，照旧命中、照旧在文件栏里列着；新面板从 0.2° 起步。

**产物在文件栏里分组。** 文件栏是一棵树：顶上是「原始数据」组，往下是各阶段分组——**1D 产物按积分设置分组**（用户 2026-09-28 第 4 条：「同一批原始数据出两组 theta 不同的 1d 图会掺在一起，应该有分组区分」）：一组一套设置、组名就写着是哪一套（「1D 产物 2θ 1–8°（当前设置）」「1D 产物 2θ 3–12° · 1000 点 · 几何 lmfp2_lab6」），当前设置那一组排最前；改之前全库只有一组、靠行尾那截「1D（2θ 1–8°）」区分，而尾巴是相对当前设置算的（坞顶范围一改，尾巴会从 A 行跳到 B 行，像两组换了身份）。「扣背景 09-25 14:03（锚点 5 个（覆盖 1.29–2.7°），窗口 2°）…」= 每次 [批量扣背景] 一组（组名带时间与参数，一眼看得出是哪一套参数的结果）。**「正在打开」有专门的记号**（用户 2026-09-28 第 5 条：「文件栏背景加深代表这个图正在打开，选中未选中仅用框内的标志表示」）：有条目开着面板 = 整行淡色 + 左侧一个实心小点，勾没勾只看框里的小勾（Qt 的选中底色已取消——原先整行深色是"最后点过的那一行"，含义只能靠猜，而且哪张图开着在文件栏里根本看不出来）。热图的行名会缩成号段（"LMFP_1_atten0-00029.tif" → "00029"）并按面板高度抽稀——81 个长名字会糊成一条黑带还把图挤到右边；对比面板**超过 12 条曲线就不再画图例**（81 行名字比数据还占地方，认曲线改看状态栏悬停读数，圆点颜色跟曲线一致）；绘图区一角的 [全关] 一次关掉所有图面板（与单个 × 同一条路径，日志报一行汇总，含几张没存过盘）。

**勾组 = 组里整组勾上**（两态：全勾亮、其余一律空格——半勾那根横线跟空格分不清，用户 2026-09-26 让去掉），整组勾上去 [对比]/[热图] 就是把那一批结果叠成一张图。条目上**双击产物 = 打开这一张的 1D 图**；**双击原始数据不出图**——原始数据能出四种图，双击只给一句指路（用户 2026-09-27：「原始数据应该双击打不开，因为原始数据可以出各种图」），想看 1D 用右键那条（菜单上明写着 1D）。分组右键 = [打开整组 1D 图]（超过 24 张先确认）。右键可以**删产物**：分组上右键 = 删掉这一组（扣背景批次连台账一起清），条目上右键 = 只删这一条——**所有产物都能在文件栏里删**，「1D 产物」组也一样（它的删除入口就在这里，不改设置也能清）。分组只在"有事发生"时重建（导入/删除、批量扣背景、清空缓存），不是定时刷新。**汇总视图不留上一次选择的记忆**：[对比] 与 [热图] 是**单槽面板**，每次按都按**当前**勾选重建（键原来编码了勾选集合，于是改勾选再按 = 又开一张、旧那张还赖在屏幕上，用户看到的是旧画面——「选了 81 条却出来二百多」就是这么来的；2026-09-28 定的规矩：「无论什么时候，都是执行当前勾选，不存在以前勾选影响现在的情况」）。混类勾选时标题直接写明构成；完成日志把来处说准（「复用 1D 缓存 81 条」，不再是看着像自己冒出来的「1D 产物 81 条」）。**盘上有什么，文件栏就显示什么**（2026-09-28）：「1D 产物」组改成**扫盘**建立（不再按当前设置正查键），所以改 2θ 范围不会让那一组空掉——那一组空着被读成"处理产物把我的 1D 文件顶掉了"（其实一份没少、也没删：2θ 范围是产物身份的一半，正查自然查不到）。按**别的设置**算的产物也照样列着，名字里标出不一样的地方（「· 1D（2θ 1–8°）」，完整说法在悬停提示里）；旧背景算法算的那批**标「旧算法，不可信」而不是藏起来**——规矩是"缓存只在用户自己删的时候才变少"。这条规矩的另一半：改动之前的老产物元数据里只有文件名，认人只能退回按名字（新产物记全路径），两个目录里同名的文件因此会含糊——测试改用唯一文件名就是为了这个。

**重建不许改"你在哪儿"**（2026-09-27）：滚动位置、收起的组、产物条目的对号、当前高亮，重建前后都一样。在这之前，重建会把产物条目的对号全部抹掉——勾好一批准备去 [对比]，中途按一次 [1D] 出图，选择就没了。

**文件栏不会再自己滚。** 分开三条路治的：① 重建（上面那条）；② **导入**原本会把当前项设成最后一条新条目、Qt 顺手把它滚进视野（导入 81 个文件，列表就停在最后一批）；③ **高亮跟随对号**原本会跳到"第一条勾选条目"——通常就是最顶上那个文件——于是取消勾选、点组节点、[全选] 都把列表拽回顶端（用户原话："一操作就跳回最顶端"）。现在第 3 条从构造上没了：当前项不是勾选条目时**直接取消高亮**（`setCurrentItem(None)` 不滚动，也不存在"同步放回 vs 下一帧才落地"的竞态——只做滚动条存取的修法留过一个时序漏洞，用户报的"没打字就跳了"就是它）。导入/改名照旧高亮新条目，但列表不动。

**出图按钮上写着"勾选 N 个"**：`[出图（勾选 162 个）]`，类型行上方另有一句构成说明"勾选 162 条：原始 81 ｜ 1D 产物 81"，并且**同一文件的原始条目和它自己的 1D 产物同时勾着**时会提醒"同一条曲线会画两遍"。这就是"选中 81 个图，怎么出来 162 条"的答案：对比没画错，是勾选集有 162 条（为了出 1D 图勾过的 81 个原始文件还留着，再点「1D 产物」组行又加了 81 条）。另外文件栏空白处/「原始数据」组右键多了 **「打开勾选的 N 张 1D 图」**——唯一一条**没有 24 张上限**的批量开图入口（只弹确认），补上视图按钮在 1D 上"超 24 张一张都不画"时缺的那条路。

**两类产物待遇不同。** 「1D 产物」就是那条原始积分曲线（只是钉在某一份缓存上），跟原始文件一个待遇：锚点、自动基线照用，也能整组进 [批量扣背景]（扣出来的结果挂在**那一份 1D 的键**下面——勾的是哪一条就扣哪一条）；「扣背景产物」才是"已完成"的：面板上强制「不扣」。**但"换套参数重做"现在有路**（用户 2026-09-28 第 3 条："套用别的配方的处理图不能二次处理了，修正"）：在产物的 1D 面板上按 [套用] 或 [采用这份结果] 时，程序**就地把它换成它底下的原始 1D 曲线**（血缘 = 产物元数据里的 `base_key`，老产物退回台账里那一批的几何/点数/2θ 范围去读 1D 缓存），配方/处理链按那条源曲线重做——所以既做得到、又不会在扣完的曲线上再扣一遍（二次相减会让曲线整体往下掉一截，看着还挺像"扣得更干净"）。[批量处理] 勾到 "处理后" 条目时走同一条路（按各自的源曲线重做，日志里写明几条是这样来的）。找不到源曲线（缓存被清过、老产物又没记血缘）时会明确拒绝并说清原因。产物条目出 1D 图 / 导出走的正是那一份产物，不重算。

## 界面工程细节

- **独立图面板**——每张图是一个 MDI 子窗口，互不牵连：可自由缩放（每次拖动记住这张图自己的画布比例）、弹出成独立系统窗口、按各自比例横排/竖排平铺；绘图区支持 Ctrl+滚轮缩放（Excel 式）。
- **每面板一行标题栏**——面板顶上一行就是它全部的壳：Home（回到这张图本来的样子：缩放/平移不算，重算才刷新）/ 放大镜 / Customize（标题、轴标签、纵轴线性/对数、图边距）/ 保存 PNG + [弹出]/[关闭]。**Home 键**（2026-09-27）与它等效，作用于鼠标最后停过的那张图。这里有个坑值得记：防手势那个标记是**一次性**的，而"重画把用户缩放过的窗口再套一遍"正是点锚点在做的事——点第二个锚点时缩放窗口就被写成了"家"，Home 从此只能回到那个放大的窗口。现在：**重画时若套用的是面板自己的视图覆盖（= 用户缩放过的窗口），一律按"手势视图"处理，不许改"家"**（`_refresh_home`）。Home 本身仍是纯看图动作：只设坐标范围（`set_xlim`/`set_ylim`），不重画、不碰任何参数。按住这一行拖 = 移动面板、双击 = 占满绘图区（原生标题栏被换成自绘的一行，整块壳从 83 px 瘦到 26 px，同样的面板高度里画布多拿 57 px）；弹出成独立窗口时系统标题栏回来管窗口管理，这一行继续提供按钮；**当前编辑对象**的那块用更深的底色标出（活动/非活动的老惯例）。
- **面板手势**——左键拖动平移；放大镜点亮后：滚轮以光标为中心缩放（每格 10%）、**左键拖框放大**（选框是自己画的，松开只改坐标范围，绝不碰数据；范围会写进该面板的快照，重画时按它摆回去、而不是被自动缩放顶掉——热图这两半原本都缺，于是它的缩放每次重画都丢；2D / 剖面 / 瀑布 也从不记——它们的轴是像素与样品行，没有 2θ / 强度那样的语义参数，走一对通用键「视图 x 范围」「视图 y 范围」，2026-09-28 一并修）；悬停时状态栏实时显示数据点读数；面板每条边都有抓握缩放手柄。
- **实时参数面板**——每个面板的数据与显示参数集中一栏（提示气泡全覆盖，分组重置/应用，面板快照）；数据组的 2θ 范围直接约束积分本身（npt 个采样点摊在区间内），缩放/平移则实时写回视图范围。
