# 界面文案规范（UI Copy Rules）

> 2026-10-02 定。此后 `src/xrd_toolkit/gui/` 里一切**用户可见**的文字
> （控件标签、按钮、悬停提示、日志、状态行、对话框、图内文字）都按本文写。
> **代码注释不受约束**（注释继续用原来的口语风格）。
> 执行检查：`tests/test_ui_copy_style.py`（禁词 + 按钮引用完整性），改了文案跑它。

## 1. 语言与混排

1. 界面文字一律简体中文；专有名词保留原文：XRD、pyFAI、PONI、LaB₆、2θ、
   Savitzky–Golay、LMFP、magma/viridis 等色图名。
2. 图内文字（图形标题、坐标轴、图例、标注，含导出图片）一律英文；
   中文数据类别的英文对照：原始数据 = Raw、1D 产物 = 1D product、
   处理产物 = Processed、基线 = Baseline、锚点 = Anchors。
3. 中文与拉丁/数字之间加一个半角空格："2θ 范围"、"1D 产物"、"3 个文件"；
   固定搭配不加："txt/chi"、"PONI1"、"Savitzky–Golay"。
4. 数字与单位：拉丁单位前加一个空格（"0.05 px"、"15 MB"、"3.2 s"）；
   "°"、"%" 紧贴数字（"0.3°"、"99.9%"）。

## 2. 标点

1. 中文句子用全角标点（，。：；？！（）「」——）。
   半角括号只用于拉丁单位，且括号前加一个空格："距离 (mm)"、"剖面角度 (°)"。
2. 省略号一律 …（U+2026）。点击后还需要输入或再选择的按钮带 …：
   "存成配方…"、"选择空扫图…"。
3. 范围用 –（en dash，不加空格）："2–3°"、"0.1–0.3°"；不用 ~。
4. 破折号一律 ——（双破折号）；不用单破折号 " — "。
5. 引用三件套：
   - 「名称」= 页面 / 区域 / 概念：「当前配置」、「处理」页；
   - [名称] = 界面按钮：[存成配方…]、[全部关闭]；
   - “文本” = 用户输入或字面文本：名字含“abc”。
   - 禁止 ASCII 引号 " "。
6. 按钮、标签、状态行、日志行末尾不加句号；完整问句可用 ？。
7. 禁止裸露的 Markdown 记号（**、_）。工具提示要强调时用 Qt 富文本
   `<b>…</b>`（setToolTip/QLabel 支持）；日志与状态行是纯文本，去掉记号或改措辞。
8. 说明性并列不用 "="（那是代码写法）："点条目行：勾这一条"、
   "高对比：色盲友好固定色序"；数学式例外（"Δ = 该列 − 当前配置"）。

## 4. 消息写法

1. 顺序：发生了什么（结论先行）→ 对象（文件名 / 条目名）→ 原因 → 怎么办。
2. 不出现开发词（见术语表末行）。必须保留的英文标识符（异常类型、字段名）
   要带中文说明。
3. 提问对话框：标题 = 无标点的名词短语；正文 = 完整句子（可结束于 。或 ？）。
   破坏性按钮用动词（[删除]、[清空缓存]、[退出并丢弃]），不用泛化的 [确定]；
   非破坏性确认才用 [确定] / [取消]。
4. 状态行：空闲 = "就绪"；进行中 = "正在… …"；完成 = "已完成：…"；句尾不加标点。
5. Qt 标准按钮（确定/取消/是/否）由启动时装入的 qtbase_zh_CN 翻译提供，
   代码里不要再手写英文标准按钮。
6. **报错文案**（2026-10-05 定：GUI 报错不要让用户困惑）：不许把裸异常甩给
   用户（反面例子：`校准失败（手动）：KeyError: 'poni1_px'`——看不懂，
   还会以为是自己操作错了）。两类分别处理，由 `gui/tasks.user_error_text`
   唯一出口：
   - **程序内部错误**（KeyError / AttributeError / TypeError 等代码 bug，
     用户不可能造成）：写成 `程序内部出错（KeyError: 'poni1_px'，不是你
     操作的问题）`；后台任务再加下一步——`——可以重试；若反复出现，请把
     这条提示发给开发者`。异常类型与原文保留在括号里，供复制反馈。
   - **其余异常**（读文件失败、规则提示）：`类型: 消息` 原样，消息必须是
     中文人话（我们抛给自己的错写在 raise 里时就要用用户语言）。
   用户可见的报错一律走这个出口，不要在各自模块另写格式化。

## 5. 引用完整性

1. 改任何按钮 / 标签文字，全工程同步 [旧名]、「旧名」的引用
   （顺手检查 `scripts/check_gui.py` 与 `docs/*.md`）。
2. 合入前 `python -m unittest tests.test_ui_copy_style` 必须全绿。

## 6. 保留例外（改它们要连数据/文件名一起动，先拍板）

1. **"处理后"已于 2026-10-02 统一为「处理产物」**（用户："严格按照市场
   规范来"）：文件栏组名、条目后缀、导出文件名尾缀（`*_处理产物.txt`）
   全用现名；旧批次缓存里存的老标签在**显示时**归一
   （`file_dock._refresh_products`），磁盘上已导出的旧文件不追改。
2. **面板标题格式**（`1D_xxx`、`校准_xxx`、`对比_A_与_B`）：下划线分隔
   保留——标题同时是默认存盘名，分隔符必须文件名安全。图标题模板里嵌入
   的这个面板名（`{display}: full azimuthal integration`）是**名字**，不按
   图内英文规则翻译。
3. **图内英文里引用中文按钮名**：如 `turn on [看环全貌] to see them`
   ——按钮实际文字是中文，引用它的名字照抄原文，不翻译。
4. **数据文件内容**（导出 txt/CSV 的表头 `2theta(deg)` 等）：数据格式，
   不是界面语言，不按 §1–§5 改——但有自己的标准，见 §7。

## 7. 导出文件规范（2026-10-02 定）

> 数据文件内容是数据格式，不按界面文案规则走，但有自己的标准：由
> `services/export.py` 唯一实现（GUI 与 CLI 同源），
> `tests/test_data_export.py` 钉住逐字格式。

### 目录与文件名

- 单个数据集：`{输出目录}/{曲线名}{后缀}`——光一个文件，不包文件夹。
  例：`outputs/lab6-00024_处理产物.txt`。**同名已存在就顺延 `_2`、`_3`…**
  （绝不覆盖已有曲线——同一条曲线两套处理参数各导一次，两份都要留下；
  新名字写进日志）。2026-10-03 定。
- 两个及以上：`{输出目录}/导出_YYYY-MM-DD_HHMMSS_{内容标签}/`，里面
  `全部数据.csv`（大集合）+ `txt/`（每条一个）；同秒重名追加 `_2`。
  内容标签 = `原始` / `1D产物` / `处理产物` / `混合`（按这批曲线实际的
  类别判定，见 `services/export.category_tag`）——两个文件夹并排站着时
  从名字就能看出装的是什么，不用逐个打开（2026-10-03 定）。
- 曲线名 = 文件栏条目显示名（原始数据 = 文件 stem；产物 = `stem_1D` /
  `stem_处理产物`）；勾"导出处理后的曲线（背景/平滑/裁剪）"导出「原始
  数据」时，名字尾缀也加 `_处理产物`——前提是链真的做了事：三项全关、
  或背景开着但没生效（「手动锚点」没点锚点 /「空扫相减」没选空扫图）
  时，数据没被动过，照实写 Raw + `chain: none`、不加尾缀，日志里也
  说一声。
- 输出目录默认 = 项目根 `outputs/` 的**完整绝对路径**（`xrd_toolkit.paths`，
  2026-10-02 起；旧行为是相对路径，跟着进程工作目录跑，攒出过第二个
  outputs）。
- 旧文件不追改：磁盘上已有的 `*_处理后/` 目录、旧的 `1d_summary.csv`
  原样保留。

### 曲线文件表头（txt / chi；全 ASCII）

```
# 2theta(deg)  intensity
# data category: Processed
# chain: bg=auto/win=0.18 -> smooth=boxcar/0.15deg -> cut=2.7-3,2.7-3.1deg
# cut: 171 points removed
# points: 4245  range: 1.001-5.900 deg
# config: lmfp1_lab6
# exported: 2026-10-02 22:55:03
```

- `data category:` ∈ `Raw` / `1D product` / `Processed`（§1.2 的英文对照，
  与界面「原始数据 / 1D 产物 / 处理产物」一一对应）；原始数据也要写清楚
  （`chain: none` + `cut: 0 points removed`）——"没做过处理"也是一种
  必须写明的事实。
- 表头**永远纯 ASCII**：`° – → 、` 这些字符在 Excel 里会乱码（用户
  2026-10-02 报的原问题），链经 `process.chain_ascii` 转写
  （`°`→`deg`、`–`→`-`、`→`→`->`、`、`→`,`）。
- `config:` 只在知道几何配置名时写（且名字本身是 ASCII）；`exported:`
  是秒级时间戳；裁剪点不写行。

### 全部数据.csv（utf-8-sig，带 BOM）

```
# exported: 2026-10-03 19:38:58
# column 2: a | category=Processed | chain=bg=auto/win=0.2 -> cut=2.5-3.2deg | cut=300 points removed | 3000 points | 2theta=1.001-7.999 deg | config=lmfp1_lab6
# blank cells = 2theta points inside a cut range (no data)
2theta(deg),a,b
0.5,1,
```

- **说明块在最上面，紧跟其后就是表头行、再往下就是数据**（2026-10-03
  用户："2theta 和名称跟数据不挨着，把无关信息放到最上面"——以前说明
  夹在表头和数据之间，81 列就是 81 行，Excel 里一滚就错位）。
- 读法：`pd.read_csv(path, comment="#")`（pandas 自动跳过注释、把第一
  行非注释当表头）。`np.loadtxt(skiprows=1)` 那句**不再适用**——注释
  行数随列数变化，"跳 1 行"没有确定含义了。
- 每列一行来源明细（类别 / 链 / 裁剪点数 / 点数与范围 / 配置）。
- 裁剪过的列那几格**留空**，不写字面 nan（0 会被当成真实强度）。
- BOM 必须：列名可能含中文（`_处理产物`），没有 BOM 时 Excel 打开
  注释/表头行就是乱码。
